# Manhole Guard — FastAPI + PostgreSQL backend

This backend is an integration starter, not a certified gas-safety system. MQ-4 and MQ-136 values are relative sensor response increases (%) only, not ppm or LEL. NORMAL/MEDIUM/HIGH are provisional demo classifications, not certified safety thresholds. An OFFLINE connection is reported separately and stale readings are changed to `UNKNOWN` in the manhole summary.

## Environment variables

Copy `.env.example` to `.env` for local work. Never commit `.env` or publish its values.

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string. Use `postgresql+psycopg://...`; legacy `postgres://` and `postgresql://` host URLs are normalized automatically. |
| `API_KEY` | Yes for POST | Shared secret required in `X-API-Key` for `POST /api/readings`. GET endpoints remain public. |
| `ALLOWED_ORIGINS` | Recommended | Comma-separated exact browser frontend origins, without trailing slash. |
| `OFFLINE_AFTER_SECONDS` | No | Reading age after which a manhole is `OFFLINE`; defaults to 30 seconds. |

Generate a strong key, for example with Python: `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Put it in the host's secret/environment settings and configure the same key on the Surface Node. Do not commit it or put it in frontend JavaScript.

## Local setup (Windows PowerShell)

1. Create a PostgreSQL database named `manhole_guard`.
2. Copy `.env.example` to `.env`, then set `DATABASE_URL` and a strong `API_KEY`.
3. Install and seed:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.seed
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/docs`.

## Existing database migration

`Base.metadata.create_all()` creates missing tables but does not add columns to existing tables. If this database was created using an earlier backend version, run the additive SQL in `migrations/001_add_reading_hardware_fields.sql` once against the existing `sensor_readings` table before deploying this version. It uses `ADD COLUMN IF NOT EXISTS` and does not delete existing data. For a new database, `create_all()` creates these columns automatically.

## Deploy to Render

The included `render.yaml` defines the web service, health check, build command, and start command. Create a managed PostgreSQL database and set `DATABASE_URL` to its **internal** connection URL. Set `ALLOWED_ORIGINS` to the exact deployed frontend origin, for example `https://your-site.example`. Render generates `API_KEY` from the blueprint; copy it securely to the Surface Node configuration. Keep `OFFLINE_AFTER_SECONDS` at 30 unless your hardware reporting interval requires a different threshold.

The start command runs the idempotent seed (`python -m app.seed`) before starting Uvicorn. Seeding inserts the six demo manholes only when they do not already exist; it does not delete existing rows. Existing databases still need the additive migration above.

## API endpoints

Public GET endpoints:

- `GET /api/health`
- `GET /api/manholes`
- `GET /api/manholes/{manhole_id}`
- `GET /api/manholes/{manhole_id}/history?limit=100`
- `GET /api/alerts`

Authenticated write endpoint:

- `POST /api/readings` — requires `X-API-Key: <shared-secret>` and returns `201`.

A missing or incorrect key returns `401`. If `API_KEY` is not configured on the server, POST fails closed with `503`.

## ESP32 payload

The existing flat payload shape in `sample_reading.json` is unchanged. The optional `timestamp` field is accepted for compatibility but ignored; `recorded_at` is always generated by the server when it receives the reading. Add the `X-API-Key` header to the Surface Node HTTP request. Send JSON with `Content-Type: application/json` to `/api/readings` over HTTPS after deployment.

## Behavior and data handling

- A manhole is `OFFLINE` when it has no reading or its latest server-recorded reading is older than `OFFLINE_AFTER_SECONDS`. Its summary `latest_reading.gas_status` is then `UNKNOWN`, never stale `NORMAL`.
- Node health history remains append-only; GET summaries select the latest row per node type deterministically.
- Gas alerts are created on gas-status transitions into MEDIUM/HIGH. SOS, sensor-fault, and node-offline alerts are created on transitions. An existing unacknowledged alert with the same manhole, severity, and message suppresses duplicates.
- `worker_motion` remains `INSIDE`, `OUTSIDE`, or `UNKNOWN` consistently with the seed data and sample payload. The current unchanged payload has no dedicated no-movement event/flag, so a no-movement alert cannot be safely inferred from it; do not interpret `OUTSIDE` or `UNKNOWN` as no movement.
- The seed is idempotent for the six base manhole records and does not delete data.

## Data flow

Probe + Worker ESP32 nodes --ESP-NOW--> Surface ESP32 --Wi-Fi/HTTPS POST--> FastAPI --> PostgreSQL --> website.

The frontend in the separate website archive still needs its own API adapter/configuration work before it will display live backend data; this backend deployment alone does not connect the browser UI.
